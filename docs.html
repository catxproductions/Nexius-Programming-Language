Syntax, built-in commands, operators, and rules for writing Nexius programs in Nexius Studio.

Quick start

Write code in the Studio editor, select Compile to check syntax, then select Run. Ctrl+Enter (or Cmd+Enter) also runs the program.

name = input("What is your name? ")
output("Hello,", name)

Comments

Use ,,, for a single-line comment and matching ... markers for a multiline comment.

,,, This line is ignored

...
This section is ignored.
It can span multiple lines.
...

Variables and values

Assign values with one equals sign. Names begin with a letter or underscore and may contain letters, numbers, and underscores.

player_name = "Alex"
score = 100
is_ready = true
score = score + 5
output(player_name, score, is_ready)

Supported values include numbers, strings, booleans (true and false), and lists.

Input and output

Text input

name = input("Enter your name: ")

Numeric input

score = numinput("Enter a number: ")

Invalid or empty numeric input produces an error. Output accepts multiple comma-separated expressions:

output("Score:", score)
output("Calculation:", 5 + 3)

Values are printed on one line, separated by spaces.

Lists

Comma-separated values inside parentheses create a list. Indexes start at zero.

numbers = (10, 20, 30)
names = ("Alex", "Sam", "Jordan")
output(numbers)
output(numbers[0])
output(names[2])

Use square brackets to read an item. The index must be a whole number within the list's bounds.

Console commands

clear()

Clears the program output console. It does not stop execution.

wait(time)

Pauses execution for the specified number of seconds. The value must be non-negative; decimal seconds are allowed.

output("Starting...")
wait(2)
output("Two seconds later.")
clear()
output("Console cleared.")

Conditions

Begin with if -- condition:. Optional branches use -- ELIF -- condition: and -- ELSE --:. Close the complete conditional with --.

if -- score >= 100:
  output("You win!")
-- ELIF -- score >= 50:
  output("Almost there.")
-- ELSE --:
  output("Keep trying.")
--

Boolean expressions can be assigned using boolIf:

is_ready = boolIf -- score >= 100 --

Loops

A while block repeats while its condition is true. Close the block with --.

counter = 0
while -- counter < 5:
  output(counter)
  counter = counter + 1
--

An instruction limit helps prevent accidental infinite loops.

Keyboard events

Use checkfor("w") inside a condition to read whether a key is currently held. Prefix a statement with perm. to keep its tracking or event listener active until the program ends. Event blocks are written by the programmer and run when the matching key event occurs.

perm.checkfor("w")

perm.on("w")press --:
  output("W was pressed")
--

perm.on("w")release --:
  output("W was released")
--

while -- checkfor("w") == true:
  output("W is currently held")
--

on(key)press and on(key)release without perm. are one-shot listeners: they run once at the next matching event. With perm., they run on every matching event until the program ends or is stopped. Key names are case-insensitive; the space bar is "space".

Counted loops

Use Loop --(amount): to run a block a fixed number of times. The amount is evaluated once when the loop starts and must be a non-negative whole number. Close the block with --.

Loop --(5):
  output("This runs five times.")
--

count = 3
Loop --(count):
  output("Repeated:", count)
--

Functions

Define a zero-argument function with define -- name():, close it with --, and call it with its name and parentheses.

define -- greet():
  output("Hello from Nexius!")
--

greet()

Language rules

  • Assignment uses one equals sign: score = 10.
  • Equality comparisons use two equals signs: score == 10.
  • if, while, and define headers end with a colon.
  • Every opened block must be closed with its own --.
  • Use the exact -- ELIF -- and -- ELSE -- marker forms.
  • Strings support straight single/double quotes and matching typographic curly quotes.
  • Indentation is for readability; block markers determine block boundaries in the current parser.
  • List indexes start at zero.
If an error points to a line, check its punctuation and the block markers around it.

Current limitations

Nexius is under active development. The browser preview parses Nexius into an internal syntax tree and executes it in a JavaScript-based runtime; it does not yet compile native machine code or WebAssembly.

  • User-defined functions currently take no parameters and return no values.
  • General function calls inside expressions are not supported, except checkfor(key).
  • Lists support creation and indexed reads; mutation methods are not implemented.
  • Classes, imports, file I/O, and native compilation are not implemented yet.
